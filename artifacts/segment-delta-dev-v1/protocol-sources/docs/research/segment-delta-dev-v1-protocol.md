# Segment delta development v1: pre-training registration

13 November 2026. Development only, no held-out writer/loader. Fixed after the
[v2 decision](toruk-custom-lm-architecture-decision-v2.md) and disposable numeric
rehearsal, before implementation, fitting or evaluation answers. Not a revision
of any old registration. All new run artifacts: `artifacts/segment-delta-dev-v1/`.

## Model, training and identities

Unchanged byte tokenizer `toruk-utf8-byte-v1`, PAD/BOS/EOS 0/1/2 and byte+3,
259 IDs; fingerprint and source SHA recorded in registration. Float32 CPU,
one Torch thread, deterministic algorithms. Segment and maximum local context
24; maximum document inputs/next-token targets 192. No dropout or KV cache.

| Cell | Model | Parameters | Neural state |
| --- | --- | ---: | ---: |
| ordinary | Existing CausalLM, width18, heads2, one layer, FFN72 | 13,914 | 0 |
| recurrent | Existing OwnedMemoryLM full path, width16, heads4, one layer, FFN64, four slots | 14,288 | 256 bytes |
| delta | New delta state/update from decision, width16, heads4, one layer, FFN116, rank8 | 14,277 | 256 bytes |

All active parameter budgets within 3%; all configurations fixed before fits.
FFN/width differences limit writer-specific causal attribution. Common-shaped
backbone tensors initialize identically by seed where possible; different shapes
use deterministic per-configuration initialization. No pretrained weights.

Fresh grammar generated by frozen `scripts/segment_delta_data.py`: 128 factual
plus 32 prose training documents; 24 factual development inputs plus 8 prose
documents. Seeds train831107/dev831109. Distinct IDs and full texts; common
entities, grammar and finite values are an IID limitation. Training labels appear
only as ordinary answer bytes in training text, with uniform next-token weight.
Train loader accepts only `split=train`. No old generator, cases, labels or
checkpoint is an input. Cases/hashes/sources frozen in registration before fits.
Six balanced categories of four: distant fact, explicit later correction by
repeated assignment, related-field/entity distractor, unknown (`?` only), exact
punctuation-sensitive copying and local fact. The four distant categories each
span filler lengths32/64/96/128; measure actual evidence-end to query-end byte
distance and segment gap. Natural prose measures ordinary byte/EOS NLL separately.
All labels are generator-authored, checked by an independent last-assignment
source check before fitting; no independent human adjudication is claimed.

Seeds113/227. Three fits each: exactly128 optimizer steps, batch two complete
documents, fixed deterministic epoch-shuffled order from existing `train_indices`,
AdamW lr.003, betas(.9,.999), eps1e-8, weight_decay.01, foreach=False,
fused=False, clip norm1.0. Uniform token-normalized full-document CE, no segment
detach, state reset between documents. Same examples/order/targets per seed for
all fits; training steps/targets are matched, measured compute is reported and
bounded. No claim of exactly equal FLOPs. No sweeps, early selection or retries.

Final optimizer-boundary checkpoint only: new `toruk-segment-delta-dev-v1` format
for every cell, with variant/config, parameter counts, optimizer, RNG, next-step,
consumed targets/cursor, train/tokenizer/runtime/source/registration identities.
Live document memory is excluded. Strict save/load/resume at drained document
boundaries; old loaders must reject the format. Never connect it to chat.

## Inference, scorer and order

One continuous BOS/history/question stream. No special question flush, symbol
table, evidence routing or forced answer tokens. All models use identical segment
reset/one-time commit schedule, including ordinary. Partial prefixes recompute
from entering state; discard provisional updates until a full segment commits.
Greedy argmax, PAD/BOS suppressed, ordinary EOS, cap8 generated IDs including
EOS. An unclosed answer fails. Scorer is frozen `segment_delta_data.score`:
generated IDs must exactly equal UTF-8 gold bytes+3 followed by EOS. No trimming,
normalization, replacement characters, or answer repair. Only `?` is acceptable
for unknown; arbitrary abstention on known facts fails.

Separate grammar-specific lexical control: split history into lines, rank by
overlap of alphanumeric query terms, ties latest; copy the right side of `=`
only if both query terms overlap, otherwise `?`. This deterministic parser
retains raw history, has no trained decoder, and receives prefix only. Charge
all scanning, tokenization, storage and output. It is a practical control on
this deliberately narrow grammar, not model learning or a contribution of delta.
It is reported separately and never substituted for either matched LM baseline.

Train order: seed113 ordinary/recurrent/delta, seed227 delta/recurrent/ordinary.
After all six fits, evaluate in those same orders; after each delta main worker,
evaluate its no-read and no-write diagnostics using that checkpoint. No new fits
for ablations. Then lexical once. Each main/ablation worker generates the24 cases
in frozen file order, teacher-forces each complete gold document in the evaluator
only after generation, and scores the8 prose documents. Inference worker receives
no gold file: loss scoring runs as a separate evaluator phase after raw IDs are
saved. Replay first input once per worker; equality of raw IDs/work/state hash
required (25 requests/worker). 10 model workers + lexical =275 requests, 264
scored answers (24 per cell; lexical once). Replays add no independent cases.
Gold edits must not affect generation; source/label separation is tested.

Freeze executable implementation hashes and sources as a second linked lock
after focused contract tests and before training. This lock adds identity, never
changes protocol/data/gates. A single-use run marker prohibits a second study
under the registration. Model/config/source/tokenizer/checkpoint mismatches,
nonfinite loss/state/gradients, replay failure, data overlap or unexpected inputs
stop the run with partial evidence; no repair or rerun under that registration.

## Fixed advancement rule

At EACH seed ALL must hold, exactly implemented by frozen `segment_delta_data.gates`:

1. Delta at least18/24 exact and >=4 more correct than BOTH LM controls.
2. On16 beyond-window cases, at least12/16 and >=4 gain against BOTH controls.
3. No category count regression against either LM, all4 unknowns exact `?`.
4. Each read/write removal loses >=2/16 beyond-window exact answers.
5. Prose NLL <=1.05x ordinary; no language-loss collapse hidden by factual score.
6. Total charged inference CPU AND wall <=.90x recurrent; training CPU AND
   wall <=1.50x recurrent. Counts/parameters/state/caps/integrity all valid.

Four-case gain avoids elevating a one-case fluctuation on this tiny development
set; category zero-regression is the conservative factual guard.10% savings
requires material total-cost improvement, not token reduction;1.5x training cap
limits buying retention with extra fitting. These are pragmatic go/no-go bounds,
not significance tests. Lexical results limit practical claims independently.
Any gate failure means **STOP this mechanism at this version**. A cap/integrity
failure stops immediately; an ordinary quality failure is reported after the
fixed matrix completes. Never inspect held-out data, tune after outputs, change
gates, rerun favorable cells or deploy. A pass supports only a new development
review, never conversational competence, generalization, novelty or superiority.

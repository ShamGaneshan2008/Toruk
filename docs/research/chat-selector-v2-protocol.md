# Chat selector v2 protocol (specified before final evaluation)

This is a new experiment. V1 data, checkpoint, and results and the M6 controlled-world checkpoint remain unchanged. The v1 ranker architecture is reused: eight lexical and position features feed a learned logistic turn score. It reads every supplied turn (maximum 20 messages and 8 KiB of message text), retains the last three and up to two older user turns above a development-selected threshold, then fits the shared Ollama chat prompt to 512 tokens. There is no persistent state or trained conversational decoder.

`scripts/build_chat_selector_data_v2.py` defines seven categories: correction, preservation of an unchanged slot, conflicting later fact, irrelevant same-person fact, long recall, two required facts, and unknown. Half of each category is short, half long. The train, development, and final splits contain 24, 8, and 4 cases per category. Each split uses a distinct seed, entity prefix, value pool, slot names, and fact/question template family. A case's `evidence_ids` are the required earlier turns; corrections label the later valid statement, not the obsolete one. Unknowns have no evidence. All source rules, seeds, and split hashes are written to the data manifest. Final cases must not be used to fit weights or threshold.

The bounded CPU pilot uses eight long training cases, 80 full-batch Adam steps, seed 173, learning rate 0.03, positive class weight 5, weighted binary cross entropy, and checks loss, save/reload, and deterministic replay. Full training uses all 168 training cases, 180 steps, and the same optimizer/seed. Development evidence-turn F1 chooses a threshold from 0.10 through 0.90 in 0.05 steps, with higher threshold winning ties. The checkpoint uses the established `toruk-chat-selector-v1` **file format**, with `protocol: chat-selector-v2` and a new SHA-256; this is a new set of weights, not the v1 checkpoint.

The pinned shared backbone is local Ollama `llama3.2:latest`, full digest `a80c4f17acd55265feec403c7aef86be0c25983ab279d83f3bcd3abbcb5b8b72`. All three methods use the same installed tokenizer/chat template, temperature 0, top-p 1, 32 output tokens, and 512 selected prompt tokens: (1) ordinary recent-turn BASELINE, (2) a nonlearned lexical overlap ranker keeping at most two older user turns plus the last three, and (3) the trained TORUK selector. The lexical comparator scores count of shared normalized question/content words, requiring a positive score; ties favor later turns. No method removes turns from the input history before its selection step.

Known-answer correctness requires **all** expected values as whole tokens and no forbidden obsolete value. Unknown correctness requires explicit uncertainty (`don't know`, `do not know`, `not supplied`, `not provided`, `no information`, or `cannot determine`) without a fabricated code or asserted slot value. Unsupported answers include unknown assertions and known answers containing a forbidden obsolete value. Evidence retention requires all labeled earlier evidence IDs after prompt fitting; unknown selection is measured as the number of unnecessary older turns. Errors are incorrect. Record raw prompts and answers, per-category and aggregate accuracy, unsupported counts, evidence retention, all-history and selected prompt tokens, selector scanned bytes and time, all Ollama prompt evaluation tokens (including metering), response latency, and before/after RAM/VRAM. This implementation's repeated Ollama calls to meter and trim are included in total cost and may dominate runtime.

Interpretation rules are fixed: report answer improvement only if TORUK exceeds **both** comparators by at least 10 percentage points, reaches 60% correctness and 80% known-evidence retention, and does not increase unsupported answers. Claim selected-token reduction at preserved quality only if both comparators reach 60% quality, TORUK is no less accurate, and selected tokens fall at least 35% against each. Claim total-resource efficiency only if quality is preserved and total prompt-evaluation tokens, end-to-end latency, and measured memory do not increase. A single synthetic run is not evidence of general semantic memory or paper readiness.
